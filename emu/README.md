# SRX-C61 whole-system emulator (MAME driver)

A [MAME](https://www.mamedev.org/) driver, `sony/srx_c61`, that models the Sony
SRX-611 SCARA robot controller and runs the original firmware of every board:
CPU (i486), SERVO (V810), Control board (2× ADSP-2115). See
`doc/emulator_plan.md` for the plan, board models and milestones.

**Current state: stages 0-4 (partial).** All four CPUs are declared and run
their firmware; the SERVO peripherals and DSP windows (stages 1-3) are modelled,
and the CPU board now has its 3× 8251A, 8254, 2× 8259A, RTC, EEPROM and PC-card
window (stage 4). The main firmware starts pSOS+ tasks; the teach-pendant link
performs the `SRX6` ↔ `TP4` handshake and the PC host link answers protocol
frames when a peer is connected.

The three serial channels open a pseudo terminal by default (MAME prints e.g.
`SRX: serial ch1 (teach pendant) pty: /dev/pts/0`). Connect to that device from
the host to drive the pendant / SRXWIN protocol.

### Parameter EEPROM (persistent)

The 8 KB CPU-board EEPROM holds the robot parameters (the `.CTR` block, see
`doc/SRX-611_firmware_architecture.md` §8.7). Both real chips read blank, so the
controller starts with **E050 line 100** until parameters are entered.

- The EEPROM is a MAME NVRAM device. Its contents are saved on exit to
  `nvram/srx_c61/eeprom_nv` (a raw 8192-byte image, the same layout as the chip)
  and loaded on the next start. Parameters that the firmware writes are kept:
  entered on the emulated pendant, or loaded as a `.CTR` file over the PC link.
- The `eeprom.bin` ROM is only the **default**, used when no saved file exists.
  `make_roms.sh` creates a blank (0xFF) one and never overwrites it. To start
  again from `eeprom.bin`, delete `nvram/srx_c61/eeprom_nv`.
- To program a real chip (HN58C66 / HN58V66A, as 28C64), take the
  `eeprom_nv` file as it is.
- Docker: the container keeps NVRAM in `/nvram`. Mount it to keep the data:
  `docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/nvram:/nvram" srx-c61-emu`.
  Without `--user`, the saved file belongs to root.
- The firmware itself writes to the EEPROM at every boot. `sys_config_validate`
  sets the first word of each of the 6 robot records to `1` (offsets `0x200`,
  `0x5F4`, `0x9E8`, `0xDDC`, `0x11D0`, `0x15C4`). So a "blank" image is no
  longer all `FF` after the first run. Test: `tests/eeprom_nvram.lua` (run it
  twice with a scratch `-nvram_directory`).

## Layout

| Path | Purpose |
|---|---|
| `src/mame/sony/srx_c61.cpp` | the MAME driver (single file) |
| `build.sh` | host build (`--docker` for the container build) |
| `Dockerfile` | multi-stage container build |
| `docker-entrypoint.sh` | container entrypoint |
| `make_roms.sh` | copy `FW/*` into `roms/srx_c61/` |
| `roms/srx_c61/` | ROM set (generated by `make_roms.sh`, git-ignored) |

## Build and run (Docker, recommended)

```sh
cd emu
./make_roms.sh                              # build the ROM set from FW/
docker build -t srx-c61-emu .               # build the image (pinned MAME mame0289)
docker run --rm srx-c61-emu                 # headless boot (SDK dummy driver)
```

Pass MAME arguments after the image name:

```sh
docker run --rm srx-c61-emu srx_c61 -seconds_to_run 5 -log -oslog   # 5 s run + trace to stdout
docker run --rm srx-c61-emu srx_c61 -video soft -window             # graphical window
```

Build-time options:

```sh
docker build --build-arg MAME_VERSION=mame0289 --build-arg MAKE_JOBS=8 -t srx-c61-emu .
```

## Build and run (host, no Docker)

Needs `build-essential git python3 libsdl2-dev libsdl2-ttf-dev`:

```sh
cd emu
./build.sh
"$HOME/opt/mame/mame" -rompath roms srx_c61 -video none -sound none -nothrottle
```

`MAME_DIR` and `MAME_VERSION` select the checkout and release.

## Tests and CI

`emu/tests/ci.sh [image]` runs the smoke tests against a built image, each with a fresh
NVRAM directory (about 20 s):

1. The handshake between the real CPU and pendant firmwares (`SRX TP: handshake PASSED`).
2. `tests/tp_keys.lua`: E050 is shown on the pendant at boot. F4 pressed at t = 15 s
   (after the old Z180 ASCI desync point) closes it and shows the teach screen.
3. `tests/eeprom_nvram.lua` run twice: the EEPROM contents persist.

GitHub Actions (`.github/workflows/emulator.yml`) builds the image and runs `ci.sh` on
pushes and PRs that touch `emu/`, `FW/` or the workflow. The Docker build uses
**ccache**: `emu/ccache/` is copied into the build stage, and CI restores and saves
it through the Actions cache, so a driver-only change does not recompile all of MAME.
In a local checkout the directory is empty, which gives a normal full build. To keep a
local cache, extract `/root/.ccache` from `docker build --target build` into
`emu/ccache/`.

## Notes

- The build uses `SOURCES=src/mame/sony/srx_c61.cpp` and `REGENIE=1`, so only the
  driver plus the MAME core and required devices are compiled (fast, small binary).
- Qt debugger is disabled (`USE_QTDEBUG=0`) and audio backends are disabled so no
  Qt/portaudio/pulse/pipewire headers are needed.
- The firmware images are the source of truth in `FW/`; `make_roms.sh` flattens
  them to the short names the driver's `ROM_START` declares.
