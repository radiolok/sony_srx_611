### Platform Outline

Outline  
The SRX platform software assists the program development of the SRX robot controller. The program development of the SRX robot controller is executed normally by the following procedure.  
\1.  Create a program using an editor.  
\2.  Compile the edited program which converts the language that the robot can understand.  If an error occurs, return to step 1. and correct it.  
\3.  Transfer the converted file to the controller.  
\4.  Operate the controller using the developed program to confirm that the robot operates as designed.  
5  If the robot does not operate as designed, return to step 1. and correct the program.  
The typical flow of program development is integrated into the SRX platform. Use the SRX platform to shorten the installation period of robots in an assembly line.  
[Initial setting when the SRX platform is used for the first time]  
[LUNA Installation]  or  [LUNA Directory Set]   When the optional [LUNA 5.0 system disk] has already been installed, select the installed directory name using the [LUNA Directory Set]. If the optional [LUNA 5.0 system disk] is not installed, install it using the [LUNA Installation]. The installation procedures must be completed before executing compiling and transferring programs.  

### Program Creation

Program Creation  
To create a new program, select [File] - [New] or select [NEW] of the tool bar. To modify an existing file, select [File] - [Open] or select [OPEN] of the tool bar.  Extensions of the programs have been determined as follows. The extension \*.lun is used for the programs of robot task, peripheral task and system task. The extension \*.pon is used for the programs of point data of robot task. The extension \*.plc is used for the PLC program. When any selection is made, a child window having the editor function is opened.  
The number in the left most end of a child window indicates the line number. The following processes are possible for program creation.  
File  
[New]    Creates a new program under the specified name.  
[Open]    Opens an existing program of the specified name.  
[Close]    Closes the currently opened program.  
[Save]     Saves the currently opened program.  
[Rename]     Changes name of the currently opened program.  
[Print]     Outputs the currently opened program to printer.  
[Printer set]    Makes the printer setting.  
[File names -1 and -2]     Displays the file names which have been opened before.  
Edit

### Compile Programs

Compiling Programs  
Compiling is the work which converts programs created by the editor, to the data format which can be understood by the robot. It also checks if symbols of the programs described by users are correct, or if commands are correctly used. The program used for compiling is called a compiler. The SRX platform can handle the following three types of compiler.  
Compiler  
[LUNNA]    Converts the LUNA program \*.lun files to \*.obj.  
[POINT]    Converts the point data file \*.pon files to \*.dat, or \*.cpn files to \*.cdt.  
[PLC]    Converts the PLC program \*.plc files to \*.cod.  
The optional [LUNA 5.0 system disk] must already be installed before executing the respective compilers. Refer to section  [LUNA Installation]  and  [LUNA Directory Set]  for more details. When an error is detected by the compiler, an error file is opened.  The line number and the error contents are displayed in the error file. Clicking a specific line of the error file will jump to the line which caused the error.  

### Send

Send  
Files are sent and received between a personal computer and a controller using the transfer function. Be sure to install the [LUNA 5.0 system disk] beforehand because the transfer programs are installed together with compiler programs when the  LUNA Installation  is executed. Before executing the transfer menu, connect the PROGRAMMING UNIT terminal on the front panel of the controller with the RS-232C terminal of a personal computer with a transfer cable. The following transfer processes are possible.  
Send  
[FILES]    Displays the program list of controller.  
[SEND]    Transfers the converted program to controller.  
[RECALL]    Transfers programs from controller to PC.  
[Error History]     Displays the error archives which have occurred in the controller.  

### Connection

Connection  
Connection means to start communication with a controller.  When establishing a connection, the file name opened with the PC (personal computer), is searched in the controller. When the same name file is found, communication is established.  When communication is established, real time monitoring of the controller status, or execution of the LUNA program becomes possible.  
Connection  
[Start Communication]    Starts communication with controller.  
[Stop Communication]    Stops communication with controller.  

### Execution and Debugging

Execution and Debugging  
When communication is established, execution of the program can be controlled from the PC (personal computer). For example, controls such as starting execution, stopping execution, executing line after a line, etc., become possible.  However, for safety reason, the control from the TP (teaching pendant) has priority over the control from the SRX platform. Therefore, an operation to give priority to PC (personal computer) must be performed from the TP side, or the TP must be disconnected from the controller before the SRX platform controls execution of programs or re-writing the values of variables.  
Press the [ON LINE TP ON/OFF] key of the TP and select PC in order to give priority to the PC.

### Special Relay

Special Relays  
The following types of pre-defined special relays are available.

ALLON     Always ON  Always in the ON status.  
AUTO     Auto  Becomes ON when the controller is in the execution mode or on-line mode.  
CLK01     0.1 second clock  A clock pulse with a 0.1 second frequency.  
CLK02     0.2 second clock  A clock pulse with a 0.2 second frequency.

Two to flash R0001 at 4-second intervals in the sample 1? A 4-second interval can be composed of 2-second OFF and 2-second ON. The 4-second interval should be programmed as it does not included in the special relay's features. Easy way to program the interval is switching ON/OFF every two seconds.  ; \*\*\*\*\*\*\*\*\*\* Sample 2 \*\*\*\*\*\*\*\*\*\*  DEF  SWITCH,  R0000 DEF  CLK4,     R0100  JP(1) := CLK2   CLK4 = ~CLK4  ; execution every two seconds JPE(1)  R0001 = SWITCH \* CLK4  
END   One execution every two seconds is confirmed by switching the special relay  CLK2  from OFF to ON in an interval of two seconds. This will be satisfied with description of  :=  CLK2. As program between  JP and JP E command lines are executed only when JP condition part is ON, expression of (CLK4 =  ~ CLK4) is implemented once every two seconds. Otherwise, CLK4 will remain unchanged. (CLK4 = ~CLK4) switches OFF to ON and vice versa, reversing itself.  
Execute the program and observe the value of R0001 by changing the R0000 value through (monitor.)  

### PLC Sample Program 3

Sample 3  Relay Flash 3        (PLC)  
This time, design program to make one-second flash and 3-second light-off at an interval of 4 seconds, the repetition of a circle of one-second ON and 3-second OFF. The following is a time chart, plotting the relations between CLK4 programmed in the sample 2 and the special relay CLK2 against the time. The time chart proves that the applicable program is made by expressions of (CLK2 \* CLK4.) The expression can be replaced with either of (~CLK2 \* CLK4,) (CLK2 \* ~CLK4,) or (~CLK2 \* ~CLK4.)  
The complete program is as follows:    ; \*\*\*\*\*\*\*\*\*\* Sample 3 \*\*\*\*\*\*\*\*\*\*  DEF  SWITCH,   R0000 DEF  CLK4,      R0100  JP(1) := CLK2   CLK4 = ~CLK4  ; execution every two seconds JPE(1)  R0001 = SWITCH \* CLK4 \* CLK2  END  Plotting a time chart is the first step to master time control. Execute the program and observe the value of R0001 by changing the R0000 value through (monitor.)  

### PLC Sample Program 4

Sample 4  Relay Blink 4         (PLC)  
Let's change the blinking speed to 4-second cycle when R0000 is OFF and 2-second cycle when R0000 is ON. It is easy if 4-second cycle CLK4 is OK. Reflect CLK4 on R0000 in case R0000 is OFF, and reflect CLK2 on R0001 in case R0000 is ON.    ; \*\*\*\*\*\*\*\*\*\* Sample 4 \*\*\*\*\*\*\*\*\*\*  DEF  FAST,  R0000 DEF  CLK4,  R0100  JP(1) := CLK2   CLK4 = ~CLK4  ; Execute every two seconds. JPE(1)  R0001 = FAST \* CLK2 + ~FAST \* CLK4  END  In this sample, since blinking becomes faster when R0000 is put ON, the label of R0000 is defined as FAST.  
When FAST is OFF, since FAST\*CLK2 is absolutely OFF, it means   R0001 = CLK4  and when FAST is ON, it means   R0001 = CLK2  Execute this program, change the value of R0000 on the "monitor" and check the value of R0001.  

### PLC Sample Program 5

Sample 5  Relay Blink 5         (PLC)  
Now let's think how to make R0001 blink in 3-second cycle in Sample 1. 3-second cycle means the repetition of 1.5-second OFF and 1.5-second ON. It seems appropriate to utilize  CLK05  which is the 0.5-second clock. Reverse R0001 whenever CLK05 changes three times. It is convenient to use an ordinary counter in handling with the number of times. Count the number of changes of CLK05 and reverse CLK3 when the number becomes 3 (id. in 1.5 seconds). Then reset the counter in order to be able to count CLK05 three times again.  
The program will be as follows.    ; \*\*\*\*\*\*\*\*\*\* Sample 5 \*\*\*\*\*\*\*\*\*\*  DEF  SWITCH,  R0000 DEF  CLK3,     R0100  C000( 3 ) := CLK05   ; Count down every 0.5 second. JP(1)    := C000   CLK3 = ~CLK3   ; Execute every 1.5 seconds.   CRST( C000 ) = ALLON  ; Reset the counter. JPE(1)  R0001 = SWITCH \* CLK3  END  The time chart of this program will be as follows. Execute this program, change the value of R0000 on the "monitor" and check the value of R0001.  

### PLC Sample Program 6

Sample 6  How to Handle Numerical Values 1     (PLC)  
Let's make a program to handle numerical values. Change the value of Keep Channel K00C from 0 to 9 in every second and repeat this action. As it is every second, the special relay  CLK1  can be used. In order to increase by 1,  INC  command seems available. To be specific, set K00C for 0 as the initial value and increase the value every second by INC command. To realize it easily, rewrite 0 the moment the value of K00C reaches 10.     ; \*\*\*\*\*\*\*\*\*\* Sample 6 \*\*\*\*\*\*\*\*\*\*  
MOV( 0, K00C )  = FIRST INC( K00C )     := CLK1  ; 1 increment CMP( K00C, 10 ) = ALLON  ; Compare with 10 and reflect on EQU. MOV( 0, K00C )  = EQU  ; If it is 10, put 0.  END  To initialize, the special relay  FIRST  is convenient. This relay becomes ON for the first scan (until the execution of  END  command) when the program starts up. That is, at the start-up of the program, the following  MOV     MOV(0, K00C) = FIRST  will be executed.  
Execute this program and check the value of K00C on the "monitor".  

### PLC Sample Program 7

Sample 7  How to Handle Numerical Values 2    (PLC)  
Let's realize in a different way from Sample 6. There is no problem for preparation of the ordinary counter described in Sample 6. In Sample 6, the value of K00C virtually becomes 10 momentarily, but there is no problem because the value of K00C is usually used between this 3-line counter program and  END  command.  ; \*\*\*\*\*\*\*\*\*\* Sample 6 \*\*\*\*\*\*\*\*\*\* MOV( 0, K00C )  = FIRST INC( K00C )     := CLK1  ; 1 increment CMP( K00C, 10 ) = ALLON  ; Compare with 10 and reflect on EQU.  
MOV( 0, K00C )  = EQU  ; If it is 10, put 0.  ; The value of K00C is usually used here.  END     In case the value of K00C is read by  OUTP(0)  command  
L001 = HIT1 L002 = HIT2 L003 = HIT3 L004 = HIT4 L005 = START \* ~HIT4 + HIT4 \* CLK05 END  Here is a point of this program. When START is OFF, HIT1 through HIT4 are all OFF. Since the conditions of MC between  MC and MCE  are handled as AND, when START is OFF, HIT1 through HIT4 will not be ON even if the pattern of I4-I1 matches. When the first pattern (I4=ON, I3=OFF, I2=ON, I1=OFF) matches, HIT1 will be ON. Once HIT1 is ON, it keeps ON until MC becomes OFF because it handles itself as OR with +HIT1 described in the condition.  
When HIT1 becomes ON, the program goes on to HIT2. If HIT4 becomes ON, LED 5 will blink.  

### PLC Sample Program 13

Sample 13  How to Handle I/O 3        (PLC)  
Let's make the version-up of the program in Sample 12. First, set the time limit of 20 seconds. When the time is over, put out LED1 through 4. If you make it within 20 seconds, blink all the LEDs.     ; \*\*\*\*\*\*\*\*\*\*\*\*\* Sample 13  \*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\* ; Label Definition DEF  START,      I5 DEF  HIT1,        R0000 DEF  HIT2,        R0001 DEF  HIT3,        R0002 DEF  HIT4,        R0003 DEF  TIMEOVER,  R0015 DEF  FINISH,      ROO14  ; Sequence CRST( C000 ) = ~START  ; If START then do not reset the counter.

HIT2 = ~I4 \* ~I3 \*  I2 \*  I1 \* HIT1 + HIT2 ; If I4-I1 is 0011, go on to the next. HIT3 =  I4 \*  I3 \* ~I2 \*  I1 \* HIT2 + HIT3 ; If I4-I1 is 1101, go on to the next. HIT4 = ~I4 \*  I3 \*  I2 \* ~I1 \* HIT3 + HIT4 ; If I4-I1 is 0110, go on to the next. C000( 20 ) := CLK1 TIMEOVER = C000 \* ~HIT4  ; Time is over in 20 seconds. FINISH   = ~C000 \* HIT4  ; Finish if HIT4 becomes ON within 20 seconds.  
MCE  ; Output Setting L001 = HIT1 \* ~TIMEOVER \*~FINISH + FINISH \* CLK05 L002 = HIT2 \* ~TIMEOVER \*~FINISH + FINISH \* CLK05 L003 = HIT3 \* ~TIMEOVER \*~FINISH + FINISH \* CLK05 L004 = HIT4 \* ~TIMEOVER \*~FINISH + FINISH \* CLK05 L005 = START \* ~FINISH + FINISH \* CLK05  END

### [BK1], [BK2]

[BK1]  [BK2]    (LUNA)  
LUNA breakpoint  
The LUNA software has the function to stop running the program when specified conditions are satisfied.  This function is called a breakpoint. Two breakpoints can be set for each task, which are called breakpoint 1 and breakpoint 2. The following two conditions can be set for the LUNA breakpoint.  
\1.  Line pass  
When the condition of (line pass) is set and satisfied, a program is stopped at the moment of executing the specified line number. To be more specific, a program is stopped immediately before starting to execute the program of the specified line. The line number which is referred here, is the line (the numbers that are indicated on the left of the LUNA control window) of a program, and are not the labels that are specified as the destination of jump by the GO command, for example.  
When the condition of the line pass is selected, numbers of pass can also be specified as the conditions. When the line number 100 is specified and the numbers of pass 3 is specified, the program is stopped immediately before passing the 100 the line for the third time.  
\2.  INT variable matching  
When the condition of (INT variable matching) is set and satisfied, a program is stopped when the INT variable matches the specified value. When the condition of (INT variable matching) is set, numbers of change can also be specified as the conditions. When the conditions are specified such that the conditions are satisfied when the INT variable I is changed to 10, and numbers of change is set to 3, the program is stopped when the INT variable is changed to 10 from other values for the third time.  
When value of the INT variable happens to be 10 from the beginning, the next change becoming 10 is counted as the first time because change alone is counted.  
(NOTE)  
The breakpoint setting is cleared when a program is initialized, or re-transferred or when the main power is turned off.

### [BK1], [BK2]

[BK1]  [BK2]    (PLC)  
PLC breakpoint  
The PLC software has the function to stop running the program when specified conditions are satisfied.  This function is called a breakpoint.  Two breakpoints can be set for each task, which are called breakpoint 1 and breakpoint 2.  The PLC breakpoint can stop running program when the specified relay is either turned on or off.  In addition to it, numbers of change can also be specified.  When the change from off to on of the standard relay R0001 is specified as the conditions of the PLC breakpoint, and numbers of change 3 is also specified, the program is stopped when the relay R0001 is changed from off to on for the third time.  
(NOTE)  
The breakpoint setting is cleared when a program is initialized, or re-transferred or when the main power is turned off.

### E310

E 3 1 0 : SERVO Axis 1 torque limit error     [Contents]  
The 1st axis load exceeded limits.  
[Countermeasure]  
Indicates that the torque command value for the servo amplifier has exceeded specified limit ranges during calculation in the servo board, which is composed of position and speed control programs. The reason for this could be any of the following:  
(1) Mechanical loads have been exceeded  
Grease temperature in the speed reducer, quantity of grease, or a mechanical fault in the speed reducer. Re-confirm the structure of the robot in this event.  This confirmation is especially necessary when mechanical impact has occurred.  
(2) Electrical connections  
Fault in the power cable between the controller and robot. Fault in the wiring within the robot. Confirm the condition of the power cable and the connection of all connectors used for internal wiring, especially when an impact has occurred. The chance of the fault being electrical is large when errors are continually triggered when the servo is turned ON after the initial error has occurred.  
(3) Workload  
A workload exceeding limits has been carried. If there are certain work processes where this kind of workload must be carried, it is necessary to reduce the speed of operation to a level where the error is not triggered.
